# Merlin / KoolCenter agent package

RemoDroid provides an offline agent plugin for ASUS router firmware with the
Koolshare / KoolCenter Software Center. Stock Asuswrt-Merlin without that
software center is not supported by this installer.

The package contains the router agent, its required Android components, and the
plugin management page. It does not contain the panel server binary or panel
website. `remodroid-server.jar` is the phone-side component, not the panel server.

## Software Center validation fix

The tested RT-AC86U runs KoolCenter 1.9.14 on firmware
`3.0.0.4.386_46092_koolshare`. Its existing installer,
`/koolshare/scripts/ks_tar_install.sh`, checks for a `.valid` file containing
`hnd` in the extracted plugin directory. The original package omitted this
file, so Software Center rejected it as an incompatible platform package.

The fix adds [packaging/merlin/deploy/.valid](../packaging/merlin/deploy/.valid)
with this content:

```text
hnd
```

The archive must preserve the hidden file and use this layout:

```text
remodroid/
  .valid
  install.sh
  scripts/
  init.d/
  webs/Module_remodroid.asp
  res/
  remodroid/
    bin/remodroid-agent
    phone/
    agent.ini.example
    normalize.awk
    version
    arch
```

This satisfies the existing platform check. It does not modify or disable
Software Center validation. The plugin installer also executes the packaged
agent with `-h` to check binary compatibility before changing an installation.

Although the RT-AC86U kernel reports `aarch64`, the **armv7** package was tested
on this device. The marker alone does not prove binary compatibility on other
models; the AArch64 package has not been tested on this router.

## GitHub Actions

[The build workflow](../.github/workflows/build.yml) builds Linux and OpenWrt
packages first, then runs a separate **Build Merlin agent offline packages**
step for `armv7` and `aarch64`:

```text
remodroid-<version>-merlin-armv7.tar.gz
remodroid-<version>-merlin-aarch64.tar.gz
```

Both files are included in `SHA256SUMS` and the `packages` artifact. Builds
triggered by a `v*` tag also attach them to the GitHub Release. These workflow
changes have been validated locally; a hosted Actions run has not yet been
verified for this revision.

For a local build, prepare `build/out/<arch>/remodroid-agent` and the Android
files under `build/android/`, then run:

```sh
make package-merlin VERSION=0.3.4 ARCH=armv7
```

Alternatively, reuse matching release components:

```sh
BIN=/path/to/release/bin \
PHONE=/path/to/release/phone \
./packaging/merlin/build.sh 0.3.4 armv7
```

Output goes to `build/packages/`. The general `packaging/package.sh` script
builds Linux/OpenWrt packages; the workflow invokes the Merlin builder
separately afterward.

## Installation and enrollment

1. Open **Software Center → Manual installation** and upload the `.tar.gz`
   directly, without extracting it.
2. Open **RemoDroid** from the installed plugins, or visit
   `/Module_remodroid.asp` after logging into the router.
3. Paste the complete command generated by the panel into the enrollment box:

   ```sh
   remodroid enroll --panel https://panel.example.com --code XXXX-XXXX
   ```

4. Click the bind-and-start button. Successful enrollment saves the device
   identity and starts the agent. Failed enrollment preserves the existing
   configuration. Stop the agent before binding it again.
5. Enable USB debugging on the phone and approve the router's ADB key when
   prompted. Use the logs to confirm panel and phone connectivity.

The page parses the panel URL and enrollment code; it does not execute the
pasted command as shell code. Advanced INI editing remains available in a
collapsed section. When migrating an identity from another machine, stop that
machine's agent before starting the router's instance.

Installation does not automatically start the agent. Upgrades stop it and
preserve configuration, keys, and the autostart selection; start it manually
after upgrading. Uninstallation preserves configuration and ADB keys but
removes the autostart marker.

## Native interface and firmware compatibility

The page follows the existing Clash plugin's ASUS layout: `show_menu()` builds
the top banner and sidebar, while `FormTitle`, `FormTable`, and `button_gen`
provide native styling. Plugin CSS is scoped to `#remodroid`.

On the tested firmware, `/res/remodroid.css?v=2` returns **404**, whereas
`/res/remodroid.css` returns **200**. Asset references therefore omit query
parameters. This fixes the unstyled white input boxes. Textareas use a gray-blue
background and automatically adjust their height; long content scrolls within
the configured maximum height instead of requiring manual resizing.

The firmware does not provide a `timeout` command. Enrollment uses a shell
watchdog to limit the agent's enrollment process to approximately 15 seconds.

## Memory-only logs

The tested router mounts `/tmp` as `tmpfs`. Like Clash's logs under `/tmp`,
RemoDroid's runtime files stay in RAM:

| Location | Purpose |
| --- | --- |
| `/tmp/remodroid/agent.log` | Agent output |
| `/tmp/remodroid/enroll.log` | Enrollment output |
| `/tmp/remodroid/` | PID, socket, lock, temporary configuration, rotation files |
| `/jffs/configs/remodroid/` | Persistent configuration, ADB keys, autostart marker |
| `/koolshare/remodroid/` | Installed program and phone components |

Log polling and rotation do not write to JFFS. Every five seconds, the watcher
checks whether the agent log exceeds 256 KiB and, if so, retains its last 150
lines. This is a periodic threshold, not a strict size cap. Runtime logs
disappear when the router reboots. Persistent writes are reserved for installing
files, saving configuration, successful enrollment, key creation, and changing
the autostart option.

## Validation

```sh
python3 tests/merlin.py
node --check packaging/merlin/deploy/res/remodroid.js
node tests/merlin-ui.cjs
actionlint -shellcheck='' .github/workflows/build.yml
```

The browser test requires Playwright and a browser. `PLAYWRIGHT_MODULE` and
`BROWSER_BIN` can point to existing installations. It uses a firmware API
fixture, not a live router login.

Local checks cover both package architectures, exclusion of the panel server,
the `.valid` marker, configuration normalization, installation and upgrade
preservation, process lifecycle, enrollment success/failure, command parsing,
input rejection, styling, automatic textarea height, and uninstallation.

On 2026-10-17, the RT-AC86U passed first-install and upgrade checks through its
native Software Center installer. The ARMv7 package used approximately 1.2 MiB
of installed space. Earlier browser checks against the router's real RPC
verified configuration saving, autostart toggling, process start/restart/stop,
and log clearing. The router also passed an enrollment connection-failure check
without changing its configuration.

Real phone/panel enrollment, reboot behavior, and the complete logged-in browser
upload flow have not been verified. The final native menu appearance was not
covered by the fixture browser tests. The router's clock was set to 2018 during
testing; correct its time before using WSS/TLS connections.
